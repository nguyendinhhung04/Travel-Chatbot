 # Giai đoạn 6 — Xây dựng Chat API

  ## Bước 1 — Cấu hình Django REST Framework

  - Thêm rest_framework vào INSTALLED_APPS.
  - Không thêm dependency vì DRF đã có trong requirements.txt.
  - Không cấu hình authentication, permission hoặc pagination riêng.

  ## Bước 2 — Tạo serializer cho request

  Tạo chatbot/serializers.py với ChatRequestSerializer:

  class ChatRequestSerializer(serializers.Serializer):
      message = serializers.CharField(
          allow_blank=False,
          trim_whitespace=True,
      )

  Serializer chịu trách nhiệm:

  - Bắt buộc có message.
  - Chỉ chấp nhận chuỗi.
  - Loại bỏ khoảng trắng đầu và cuối.
  - Từ chối câu hỏi rỗng bằng lỗi 400 Bad Request.
  - Không nhận top_k, conversation ID hoặc các tùy chọn RAG khác.

  ## Bước 3 — Tạo hàm định dạng nguồn

  Trong chatbot/views.py, tạo helper nhỏ chuyển RAGResult.documents thành:

  [
    {
      "title": "Hoạt động tại Huế",
      "source": "destinations/hue/activities.md"
    }
  ]

  Quy tắc:

  - Lấy title và source từ metadata.
  - Loại trùng theo cặp title/source.
  - Giữ nguyên thứ tự Retrieval.
  - Dùng "Không rõ" và "unknown" nếu metadata bị thiếu.
  - Không trả nội dung chunk cho frontend.

  ## Bước 4 — Tạo API view

  Tạo ChatAPIView kế thừa APIView:

  1. Nhận JSON từ request.data.
  2. Validate bằng ChatRequestSerializer.
  3. Gọi answer_question(message) đúng một lần.
  4. Lấy answer và documents từ RAGResult.
  5. Định dạng danh sách nguồn.
  6. Trả response 200 OK:

  {
    "answer": "...",
    "sources": [
      {
        "title": "...",
        "source": "..."
      }
    ]
  }

  Nếu không Retrieval được tài liệu, vẫn trả 200 OK:

  {
    "answer": "Knowledge Base hiện chưa có đủ thông tin.",
    "sources": []
  }

  ## Bước 5 — Xử lý lỗi dịch vụ

  Bao quanh lời gọi answer_question() bằng xử lý exception:

  - Ghi đầy đủ exception vào log của Django để phục vụ debug.
  - Không trả exception, API key hoặc thông tin nội bộ cho frontend.
  - Lỗi Gemini, embedding, Chroma hoặc cấu hình RAG trả 503 Service Unavailable:

  {
    "error": "Chatbot hiện không thể trả lời. Vui lòng thử lại sau."
  }

  Các lỗi request để DRF tự xử lý:

  - Thiếu hoặc sai message: 400 Bad Request.
  - JSON không hợp lệ: 400 Bad Request.
  - Phương thức khác POST: 405 Method Not Allowed.

  ## Bước 6 — Đăng ký URL

  - Tạo chatbot/urls.py với route chat/.
  - Trong config/urls.py, đăng ký app dưới prefix api/.
  - Endpoint cuối cùng:

  POST /api/chat/

  ## Bước 7 — Kiểm tra thủ công

  Không yêu cầu viết unit test mới.

  Thực hiện:

  1. Chạy:

  .\.venv\Scripts\python.exe manage.py check

  2. Khởi động server:

  .\.venv\Scripts\python.exe manage.py runserver

  3. Gọi API với câu hỏi có trong Knowledge Base:

  Invoke-RestMethod `
    -Method Post `
    -Uri "http://127.0.0.1:8000/api/chat/" `
    -ContentType "application/json; charset=utf-8" `
    -Body '{"message":"Huế có những hoạt động gì?"}'

  4. Kiểm tra các trường hợp:
  - Lỗi dịch vụ RAG trả 503 và không lộ thông tin nội bộ.
  ## Bước 8 — Cập nhật tài liệu

  - Thêm hướng dẫn gọi /api/chat/ vào README.

  ## Giới hạn của giai đoạn 6

  - Không tạo model hoặc migration database.
  - Không lưu lịch sử hội thoại.
  - Không thêm service/repository layer.
  - Không hỗ trợ streaming, authentication, CORS hoặc rate limiting.
  - Không cho frontend thay đổi top_k; tiếp tục dùng cấu hình mặc định là 5.
  - Không sửa pipeline RAG đã hoàn thành ở giai đoạn 5.
